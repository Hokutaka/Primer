# 文字列の設計

[English](strings.en.md)

## 値の意味

`string`は不変なUTF-8の値です。`mut`な束縛への再代入は、保存していた文字列そのものを書き換える操作ではありません。コピー済みの値や、関数に渡した値は変化しません。

比較は内容全体で行い、Unicodeの正規化や大文字・小文字の変換はしません。途中のNULも内容の一部です。構文と演算の規則は[言語リファレンス](../reference/language.ja.md#文字列)に記載します。

## 観測と表現

| 段階 | 現在の表現 |
| --- | --- |
| Primer IR | `string`型と解釈済みの文字列。元の引用符付き表記はSpanで追える |
| Bytecode | `push.string`、文字列型の保存・比較・出力命令。ソース由来の命令はNodeIdとSpanを保持する |
| VM | 所有するRustの`String`。値のコピー時に内容を複製する |
| C | 読み取り専用データの場所と、UTF-8のバイト数を持つ構造体 |
| LLVM | `%primer.string = type { ptr, i64 }`と、モジュール内の静的なバイト列 |
| QBE | 8バイトの長さとUTF-8データを持つ読み取り専用領域への64ビット参照 |
| WAT | 非公開のlinear memory内に置いた長さ付きデータへの32ビット参照 |
| Windows x64直接アセンブリ | 読み取り専用データへの参照をレジスタ・スタックスロットで保持 |

IRとbytecodeのテキスト表示は、改行や制御文字をエスケープします。`print`は内容をそのまま出力します。表示の都合で値を変更しません。

共通の意味はPrimer IRで確定し、格納・コピー・命令・呼び出し規約の選択は各lowererの内側で行います。EmitterはバックエンドIRから成果物を生成し、Primerの型や意味を再解釈しません。表現を一種類に揃えることより、それぞれの変換と理由を観測できることを重視します。観測境界は既存の`emit-ir`と出力成果物のままです。

## Cでの保存期間

```c
typedef struct primer_string {
    const unsigned char *data;
    size_t length;
} primer_string;
```

現在はすべての文字列がソースのリテラルから作られます。データはCの文字列リテラルとして出力し、実行終了まで保持します。関数から文字列や文字列入りの配列を返しても、参照先は失われません。

代入では保存場所とバイト数をコピーします。データ自体を共有しても、Primerにはその中身を書き換える操作がないため、値の不変性を保てます。共有の有無やアドレスではなく、内容で等値比較します。文字列用の`malloc`・`free`や参照カウントは不要です。

この表現は実行時に文字列を新しく生成しない現在の機能範囲に対するものです。連結や外部入力のメモリ管理は含みません。また、生成Cの構造体を外部連携用の安定したABIとして定めるものではありません。

## バイト列と評価順

リテラルの各バイトは固定3桁の8進エスケープで出力します。Cコンパイラの文字コード設定に日本語の解釈を任せず、引用符などがCコードとして解釈されることも防ぎます。

等値比較はバイト数を確認してから`memcmp`で行い、表示は`fwrite`の後にLFを加えます。`strlen`や`strcmp`は使いません。Windowsでは文字列を使うプログラムの標準出力をバイナリモードにし、CR・LF・NULを保ちます。数値だけの既存プログラムは従来のテキストモードのままです。

Cが評価順を保証しない式に複数の作用や失敗し得る処理がある場合は、関数内の一時変数へソース順に保存します。短絡評価の右辺やループの条件・更新から評価を外へ移しません。束縛名にはPrimer IRのIDも含め、同名変数や補助関数との衝突を避けます。

## LLVMでの表現とターゲット

LLVMでも文字列の内容は実行終了まで保持する定数です。各リテラルを`private unnamed_addr constant [N x i8]`へlowering時の出現順に保存し、UTF-8の各バイトを固定2桁の16進エスケープで出力します。終端NULは追加せず、元のバイト数を`i64`で保持します。空文字列ではデータを読みません。

文字列、文字列入りの積型、入れ子配列はLLVMの集約値としてコピーし、関数の引数・戻り値にも同じ表現を使います。内容への書き込みや動的確保はありません。共有や最適化によるリテラル統合に関係なく、長さと全バイトで等値比較します。この内部表現は外部C ABIとの互換性を保証しません。

表示は`putchar`で各バイトを出力した後、LFを加えます。バイトは符号なしで`i32`へ拡張するため、UTF-8の上位ビットも保持します。数値の`printf`、真偽値の`puts`と同じ標準出力を使い、出力順を保ちます。比較ループと出力ループは生成LLVM上で読めます。大量の文字列出力に対する性能最適化は今後の課題です。

文字列を使うLLVM出力には`--target`を必須とします。現在の指定は次の2種類です。

| ターゲット | 標準出力の初期化 |
| --- | --- |
| `x86_64-unknown-linux-gnu` | モード変更なし |
| `x86_64-pc-windows-msvc` | CRTの標準出力（記述子1）に`_setmode(1, 32768)`を実行し、バイナリモードにする |

Windowsの初期化は、明示的な`main`の呼び出しも含めて最初のPrimer処理より前に行います。失敗時は終了コード1で停止します。文字列を使うプログラムでは数値や真偽値の末尾もLFになります。文字列を含まない既存プログラムは、ターゲット未指定の生成と従来の出力モードを維持します。

指定は生成物の`target triple`に残します。コンパイラのホストOSや環境変数から選びません。未使用の定義も含めて文字列があるのに指定がなければ、ソース位置付きで診断します。下流のClangにも同じターゲットを渡してください。異なるターゲットへの上書きは、生成済みのOS依存処理を変換しません。

LLVM loweringは式をソース順に命令化し、短絡評価やループの内側に必要な分岐を残します。ターゲット指定は生成条件を選ぶデータであり、外部プログラムの起動やコンパイラへの干渉を許可するものではありません。

根拠となる仕様は[LLVMの定数表現](https://www.llvm.org/docs/LangRef.html#constants)、[target triple](https://www.llvm.org/docs/LangRef.html#target-triple)、[Microsoft CRTの_setmode](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/setmode?view=msvc-170)です。

## QBE・WAT・直接アセンブリでの保存と受け渡し

この3経路では、リテラルごとに「8バイトの長さ＋元のUTF-8バイト列」を静的に配置し、その先頭への参照を文字列値として保持します。関数の引数・戻り値、積型のフィールド、配列の要素も同じ参照です。長さも内容も実行中に書き換えず、終端NULを追加しません。文字列同士の共有・統合をPrimerが暗黙に最適化することもありません。

再代入は変数や配列要素が持つ参照の置き換えです。共有する参照先が不変なので、以前のコピーは変わりません。積型・配列自体のコピーには既存の`blit`、メモリのload/store、スタックスロットのコピーを使います。動的確保や参照カウントは不要です。この実装上の参照はPrimerのポインタ型や外部ABIを追加するものではありません。

QBEは読み取り専用の`.rodata`にデータを置き、`loadl`で長さ、`loadub`で各バイトを読みます。文字列では`--target x86_64-unknown-linux-gnu`を必須にし、生成物へターゲットと`qbe -t amd64_sysv`の対応をコメントで残します。現在のPrimerの文字列対応はこの組み合わせを対象とします。後続のQBEに別のターゲットを渡しても、Primerが実行環境を変換したことにはなりません。

直接アセンブリは既存のWindows x64ターゲットを使います。長さとデータは読み取り専用領域へ置き、参照は`RAX`や8バイトのスタックスロットで運びます。比較時には左辺を退避してから右辺を評価し、補助関数へ渡します。出力の補助関数はWindows x64のshadow space・スタック境界・保存レジスタの規則を守ります。最初のPrimer処理より前に`_setmode`を実行し、失敗時は終了コード1で停止します。

WATではデータを非公開のlinear memoryに置き、32ビットのアドレスで参照します。8バイトの長さヘッダはリトルエンディアンで、現在のwasm32の処理は下位32ビットを読みます。メモリ領域とページ数はlowering時に決定し、文字列データを実行中に確保しません。等値比較は`i32.load8_u`と分岐に変換します。

### WATの出力と外部との境界

文字列を使うWATは`primer.write_byte(i32) -> void`をimportします。生成コードが内容の各バイトを読み出して0〜255の値として渡し、最後にLF（10）を渡します。ホストは渡されたバイトを順番どおりに保持し、文字コード変換や改行変換を挟まない契約です。数値と真偽値の整形には既存の`print_i64`・`print_f32`・`print_f64`・`print_bool`契約を使います。

出力のためにmemoryをexport/importしません。ホストへ文字列の参照先を渡さず、読み出したバイト値だけを渡すため、出力インターフェースから内容を書き換える窓口を増やしません。これは実行時の出力契約であり、コンパイラの観測APIや観測からの制御を追加するものではありません。

## 検証範囲

Cのスナップショットに加え、実際の生成Cを最適化あり・なしでコンパイルし、VMの出力とバイト単位で比較します。日本語、空文字列、NUL、改行、正規化しない比較、コピー、関数からの返却、入れ子配列、評価順、同名変数を検査します。メモリ検査にはAddressSanitizerとUndefinedBehaviorSanitizerも使います。

LLVMのスナップショットはLinuxターゲットを明示して固定します。`cargo test --test llvm_strings`はWindows/Linuxの対応ホスト上で、生成LLVM・生成C・VMと既知の期待値を最適化なし・`-O2`で比較します。CR/LFを正規化せず、関数返却、積型、入れ子配列、コピー、評価順、短絡評価、範囲外アクセスも検証します。`PRIMER_TEST_LLVM_CLANG`と`PRIMER_TEST_CC`を指定するとコンパイラ不足を失敗にし、CIでは両OSで比較を必須とします。未指定で既定コンパイラがなければ理由を表示して実行比較をスキップします。

`string-values`の観測fixtureは全8成果物を固定します。`tests/support/string_cases.rs`の共通入力と既知の期待値を、VM・C・LLVMに加え、`cargo test --test string_routes`でQBE・WAT・直接アセンブリでも検証します。出力バイトの一致、評価順、短絡評価、コピー後の独立性、範囲外アクセスでの停止を分けて確認します。未使用の既定値にだけ文字列がある場合も、WindowsのC・LLVM・ASMが同じ出力モードを選びます。

QBEはLinux x86-64、ASMはWindows x64で実行します。WATはWABTで検証・変換してNodeのWebAssemblyエンジンで実行し、公開要素が`main`だけであることも検査します。テスト用ホストの浮動小数点出力は共通fixtureの正確な値`1.5`に限定しており、一般的な数値整形実装ではありません。実行できない経路は理由を表示し、成功した比較とは区別します。CIでは両OSのジョブを合わせて全経路の実行を必須にします。

開発用ツールは`PRIMER_TEST_QBE`、`PRIMER_TEST_ASM_CLANG`、`PRIMER_TEST_NODE`、`PRIMER_TEST_WAT2WASM_JS`（WABTの`bin/wat2wasm`）で明示できます。指定したツールがない場合はテスト失敗です。WABTの導入例は`npm install --prefix target/wasm-tools --no-audit --no-fund wabt@1.0.39`です。ツールの起動は開発用テストの責務で、Primerの生成コマンドには追加しません。
