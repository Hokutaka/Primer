# u64の意味と表現

`u64`は0から18446744073709551615（2^64−1）までの整数です。i64の正の範囲を超える個数や、最上位ビットまで使う64ビットのフラグを、そのまま数値として表すために追加しました。既定の整数型はi64のままです。`value: u64 = 18446744073709551615;`または`18446744073709551615u64`と明示します。

## Primerの意味を先に決める

型、数値、演算、変換、評価順はPrimer IRまでに確定します。IRとbytecodeには`u64`と正の十進数値を残し、ソース位置も保持します。VM・生成C・生成LLVM・QBE・WAT・Windows x64アセンブリが同じ数値と失敗条件を実現します。観測するために、プログラムの値を外部から変更できる口を増やすことはしません。

算術と左シフトで範囲を超えたら停止します。0から1を引いて最大値にするような折り返しはありません。右シフトは0で埋め、シフト数は0〜63だけを認めます。`~`は64ビット内の反転です。除算・剰余の右辺が0なら停止します。符号付き整数とは暗黙に混ぜず、明示変換で数値を保てる場合だけ受け渡せます。符号なし型への負号は`-0u64`も診断します。

配列、構造体、関数でも値として扱います。mutな束縛への再代入と配列要素の更新は既存の規則に従い、コピーした値は独立です。左から右への評価、一度だけの評価、短絡評価を保ちます。添字と`byte_len`の結果は引き続きi64であり、u64の添字は明示変換が必要です。

## 格納型と数値を混同しない

| 経路 | 表現と処理 |
| --- | --- |
| Primer IR・bytecode・VM | 整数型とi128の保持領域。i64最小値からu64最大値までを正確に保持し、元の型の範囲を検査 |
| C | `uint64_t`、`UINT64_C`、演算前の範囲検査、符号なし表示 |
| LLVM | i64のビット列、`icmp u*`・`udiv`・`urem`・`lshr`、検査後に演算 |
| QBE | lのビット列、符号なし比較・除算・変換命令、検査後に演算 |
| WAT | i64のビット列、`*_u`命令と明示的な検査 |
| Windows x64 ASM | 64ビットレジスタ、carry・unsigned条件・`divq`・論理右シフト、SSE2で正確な変換 |

内部の保持領域をi128にしたことは、言語のi128対応を意味しません。生成先の格納幅は64ビットのままです。LLVMなどに負の即値が見えても、それはビット列の表記であり、Primerのu64が負になったわけではありません。lowererがこの表現を選び、emitterはバックエンドIRから出力します。外部ABIやバイト列の読み書きは今回の範囲に含みません。

## 変換と出力

`u64(x)`と`convert<u64>(x)`は同じ意味です。整数間は範囲を検査します。浮動小数点との変換は範囲検査と逆変換の一致で数値の保持を確かめます。最大値のf64変換は2^64へ丸められるので失敗します。2^64−2048はf64で正確に表せ、往復できます。浮動小数点からは小数部分、負数、負のゼロ、NaN、無限大、2^64以上を拒否します。

WATの新しい出力契約は`primer.print_u64(i64) -> void`です。ホストは64ビットを符号なしとして十進表示し、LFを続けます。JavaScriptでは`BigInt.asUintN(64, value).toString()`を使い、Numberへ変換しません。メモリは公開しません。必要なプログラムだけがこの関数をimportします。LLVM・QBEの文字列出力で必要なターゲット指定など、既存の実行環境の契約は維持します。

## 動かして確かめる

`cargo run -- run examples/u64_values.prim`は最大値、64個のフラグ、値コピー、関数、正確な変換を示します。`emit-ir`・`emit-bytecode`・`emit-c`・`emit-llvm --target x86_64-unknown-linux-gnu`・`emit-qbe --target x86_64-unknown-linux-gnu`・`emit-wat`・`emit-asm`でも同じ入力の表現を観察できます。

テストは既知の出力とVMを照合し、CとLLVMでは-O0/-O2、QBEはLinux、直接アセンブリはWindows、WATは出力専用のNodeホストで実行します。最大値、最上位ビット、符号なし比較、0との演算、全数値型との変換、精度境界、失敗時の停止を比較します。
