# モジュール・名前空間・公開範囲

[English](modules.en.md)

## 目的

型と関数を別ファイルへ移しても、値・評価順・コピーの独立性・停止理由を変えず、失敗した定義ファイルまで追えるようにします。モジュールはコンパイル時の名前解決です。実行中の共有状態や外部からの干渉を追加しません。

```primer
import "values.prim" as values;

item: values::Reading = values::reading(18446744073709551615);
print(item.amount);
```

```primer
// values.prim
pub type Reading {
    amount: u64,
}
pub fn reading(amount: u64) -> Reading {
    return Reading { amount: amount };
}
```

## 名前と公開範囲

- `import "相対パス.prim" as 別名;`をファイルの定義・文より前に書きます。別名は必須です。`import`・`as`・`pub`は予約語です。
- 外部の型・関数は`別名::名前`で参照します。自分のファイルの型・関数は修飾なしで参照します。他のファイルに同名の定義があっても衝突しません。
- 定義は既定でファイル内だけに公開します。外部へ出す定義に`pub fn`または`pub type`を付けます。関数と型の公開指定は別々です。
- `pub type`の全フィールド・既定値がその型の公開内容です。フィールド単位の非公開指定や不透明型はありません。公開関数の引数・戻り値、公開型のフィールドには、非公開型を配列内も含めて使えません。
- 公開関数の本体は同じファイルの非公開補助関数を呼べます。import側からその補助関数を呼ぶことはできません。
- 別名の重複、別名と型・関数・変数・引数の衝突を診断します。組み込み型名、`infer`、`convert`、`byte_len`も別名には使いません。
- 同じファイルを異なる別名で読み込むことは可能です。同じ物理ファイルの型は同じ型になります。依存が枝分かれして合流しても、定義を二重登録しません。

別名はそのファイルだけのものです。再export、ワイルドカードimport、複数段の`a::b::name`、外部の変数へのアクセスは未対応です。利用するファイル自身で必要な依存を明示します。

## 読み込みと実行

相対パスの基準はimportを書いたファイルのディレクトリです。CLIを起動したディレクトリや環境変数の検索パスから補いません。パスは`/`区切りの相対`.prim`に限定し、`..`による親ディレクトリへの参照は可能です。絶対パス・ドライブ指定・バックスラッシュ・制御文字は診断します。入口ファイルのCLI引数にはOSの通常のパスを使えます。

ファイルの重複・循環判定にはOSが解決した実体のパスを使います。シンボリックリンクから読み込む場合、相対importも実体側のディレクトリを基準にします。別パスのハードリンクは別モジュールとして扱います。入口、続いてimportの記述順の深さ優先でファイルIDを割り当てます。循環依存は診断し、読み込みの入れ子は128段までです。ディスク上のファイルはUTF-8として読み、本文のUnicode正規化やCR/LF変換は行いません。

**読み込まれるファイルにはimport・型・関数の定義だけを許します。** トップレベルの変数宣言や`print`は、未使用の依存でも診断します。初期化が必要なら関数を作り、入口から呼びます。読み込まれる側の`main`も通常の関数で、自動実行しません。入口では従来通りトップレベル文、または引数なし・`void`の`main`を使い、両方は混ぜません。

未使用の公開・非公開定義も型検査と生成の対象です。型・引数数・再帰などの既存制限はモジュールで回避できません。ターゲットの指定や文字列・数値の意味も全経路で従来通りです。

## コンパイラ内の処理と観測

`modules::load(entry)`がファイルを解析してimport・公開範囲を解決し、名前が衝突しない共通ASTを作ります。その後の意味解析・共通IR・各loweringを共有します。生成先ごとにモジュールの意味を解釈し直しません。内部名は`module_<file ID>_<定義名>`となり、入口の関数`main`だけは入口として残します。元の表記とバイト範囲は[ファイル付きSpan](source-files.ja.md)から追えます。

従来の`compile(&str)`等はファイルI/Oを行わず、importやpub宣言にファイルAPIの利用を求めます。import/pubを使わないCLI入力の成果物・診断は従来通りです。モジュール入力では入口を含めて数値のファイルIDを持ち、実行時停止には`file=N`を記録します。

```sh
primer emit-sources examples/modules/main.prim -o sources.json
```

これは`primer-sources-v1`形式のJSONで、登録順の`files`配列に`id`・`name`・`text`を保存します。名前と正確な本文を出す操作なので、明示したときだけ実行します。生成プログラムのメモリや実行への介入を公開する操作ではありません。本文とコンパイラ版を合わせて`file`・`node`・`bytes`を解釈します。IDは編集をまたぐ永続IDではありません。

`observe-native.cjs`も元の入口から読み込み、`sources.json`を成果物として保存・ハッシュ記録します。観測前後の一覧・本文が変われば失敗にします。ただし、複数のCLI呼び出しをまたいでファイルシステムをロックする仕組みではありません。観測中は入力を編集しないでください。

## 検証と今後

[modulesのexample](../../examples/modules/README.md)には、分割した正常例・同じ内容の単一ファイル例・呼び出し先で止まる例を置いています。`tests/source_files.rs`はCLIから生成したC・LLVM・QBE・WAT・ASM・自前オブジェクトを実行し、VMの値、停止前の出力、理由、定義ファイル内の式を比較します。C・LLVMでは最適化なし/ありを比較し、Windows/Linuxの対応ターゲットで検証します。

`tests/modules.rs`はダイヤモンド状の依存、同名の私有関数、型の同一性、非公開型の公開漏れ、循環・構文・型・パスエラー、出力ファイルを失敗時に上書きしないこと、本文のバイト保持を確認します。既存の単一ファイルfixtureも維持します。

パッケージ配布、バージョン解決、再export、コンパイル時定数、別コンパイル・動的ロード、モジュールの可変グローバル状態は今回の対象外です。次の言語機能は、この単位で書けるプログラムを増やしながら、関数の引数数制限や値操作の不足を具体的なexampleで整理します。
