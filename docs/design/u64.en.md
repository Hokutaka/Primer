# u64 semantics and representation

`u64` covers 0 through 18446744073709551615 (2^64−1), supporting counts beyond the positive i64 range and flags using all 64 bits. Unsuffixed integers still default to i64. Use `value: u64 = 18446744073709551615;` or the suffix `18446744073709551615u64`.

## Resolve Primer semantics first

Types, values, operations, conversions, and evaluation order are resolved before backend lowering. Primer IR and bytecode retain `u64`, positive decimal values, and source origins. The VM, C, LLVM, QBE, WAT, and Windows x64 assembly implement the same values and failure conditions. Observation adds no external mutation interface.

Arithmetic and left-shift overflow stop execution; subtraction below zero never wraps. Right shift fills with zeros. Shift counts must be 0–63. Complement flips exactly 64 bits. Division and remainder by zero stop. Signed and unsigned operands require explicit, value-preserving conversion. Unary minus on unsigned types diagnoses even `-0u64`.

Arrays, products, and functions retain value semantics, independent copies, left-to-right evaluation, single evaluation, and short-circuiting. Mutable binding reassignment and array element updates follow existing rules. Array indices and `byte_len` results remain i64; u64 indices require explicit conversion.

## Values and storage are separate

| Route | Representation |
| --- | --- |
| Primer IR, bytecode, VM | Integer kind plus i128 storage, preserving i64 minimum through u64 maximum and checking the original type range |
| C | `uint64_t`, `UINT64_C`, checks before arithmetic, unsigned formatting |
| LLVM | i64 bits with unsigned comparisons, `udiv`, `urem`, and `lshr` |
| QBE | l bits with unsigned comparison, division, and conversion instructions |
| WAT | i64 bits with unsigned instructions and explicit checks |
| Windows x64 assembly | 64-bit registers, carry and unsigned conditions, `divq`, logical right shift, exact conversions using SSE2 |

The internal i128 container does not add a language i128 type. Generated storage stays 64-bit. A negative immediate in LLVM is a spelling of the bit pattern, not a negative Primer u64 value. Lowerers select representations; emitters consume backend IR. This change does not establish external ABI or byte I/O support.

## Conversions and output

`u64(x)` and `convert<u64>(x)` mean the same operation. Integer conversions check range; floating-point conversions check range and exact round trips. Converting u64 maximum to f64 fails because it rounds to 2^64. The value 2^64−2048 converts exactly. Float-to-u64 rejects fractions, negatives, negative zero, NaN, infinity, and values at or above 2^64.

WAT imports `primer.print_u64(i64) -> void` only when needed. The host interprets all 64 bits as unsigned, writes decimal digits, and appends LF. JavaScript hosts use `BigInt.asUintN(64, value).toString()` without conversion to Number. Memory remains private. Existing explicit runtime target contracts, including LLVM/QBE string output, remain in effect.

## Executable evidence

Run `cargo run -- run examples/u64_values.prim` for maximum values, flags, independent copies, functions, and exact conversions. The same input can be inspected through `emit-ir`, `emit-bytecode`, `emit-c`, `emit-llvm --target x86_64-unknown-linux-gnu`, `emit-qbe --target x86_64-unknown-linux-gnu`, `emit-wat`, and `emit-asm`.

Tests compare known output with the VM and execute generated C/LLVM at -O0/-O2, QBE on Linux, assembly on Windows, and WAT with an output-only Node host. Coverage includes high-bit comparisons, zero operands, all numeric conversion kinds, precision boundaries, and runtime rejection.
