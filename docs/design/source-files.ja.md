# ファイルを識別できるソース位置

[English](source-files.en.md)

## モジュール化へ進む順序

1. **今回実装した土台**：ファイルを識別するソース位置を、解析・診断・生成経路で保持する。
2. **次の段階**：ファイル読み込み、明示的なimport、名前空間、関数・型の公開範囲を設計・実装する。
3. **その後の確認**：利用者が同じプログラムを単一ファイルとモジュールに分けて書き、CLIから全経路で比較できるようにする。

現時点でimport構文やモジュールのCLI読み込みは未実装です。今回の複数ファイル例は、Rust APIから各ファイルを別々に解析し、ASTを結合して出自を検証します。これを名前解決や公開範囲の実装済みという意味には扱いません。

## 識別子と本文

`SourceMap`は呼び出し側から受け取った表示名とUTF-8本文を保持し、登録順に1から`SourceId`を割り当てます。ファイルI/O、パスの正規化、文字列のUnicode正規化は行いません。同名の登録も上書きしません。`0`は既存の`compile(&str)`やCLIが扱う匿名の単一ソース用に予約しています。

`Span`はファイル識別子と、そのファイル内の開始・終了バイト位置を持ちます。終了は範囲に含みません。日本語、NUL、CR/LFを含む本文はそのまま保存します。本文を連結した仮想的なオフセットに置き換えません。位置解決は範囲の両端が有効なUTF-8境界であることを確認し、不明なファイルや範囲を別の本文へ黙って結び付けません。

識別子は同じMap・コンパイル内でだけ有効です。Mapをまたぐ永続IDやファイルのハッシュではありません。将来のモジュール読み込み側は登録順を決定的にし、生成物と対応するファイル一覧・本文の同一性を保存する必要があります。

## 解析・診断・生成

- `lexer::lex_source`はトークンと字句診断にファイル識別子を付けます。文字列エスケープの失敗も対象です。
- parserは一つのファイルのトークンだけを受け取り、組み立てたすべての範囲で識別子を保持します。異なるファイルのトークンを連結した入力は診断します。
- `compile_source`と`compile_source_to_ir`は登録済みのファイルを解析します。ASTから共通IR、bytecode、各生成経路へ同じ範囲を渡します。
- `run_bytecode`はVM内部エラーとソース由来の停止を区別し、構造化された出自を返します。
- `render_compact_with_sources`は対応するMapから表示名・行・列を解決します。制御文字をエスケープし、不明な位置には数値のファイルIDとバイト位置を表示します。

可観測性のためにファイル名や本文を生成プログラムへ埋め込む必要はありません。登録済みファイルの停止記録では、[runtime-v1](runtime-diagnostics.ja.md)の`node`と`bytes`の間に`file=N`を付けます。未指定は匿名ソース0です。既存の単一ソースの記録は変わりません。LLVM・ASMの出自コメントにも同じ任意フィールドを加えます。

ファイルIDは不変の診断データとして渡します。「現在実行中のファイル」を共有の可変変数に保存したり、外部から変更するAPIを追加したりしません。ターゲットの選択も既存の明示的な指定を保ちます。

## 実行例と確認内容

[source_filesの例](../../examples/source_files/README.md)は、`u64`最大値、productと固定長配列、コピー後の再代入、既定の文字列値、日本語・NUL・CR/LF、短絡評価、関数内のゼロ除算を使います。

`tests/source_files.rs`は既知の期待値に加え、分割したASTと単一ソースをVM・C・LLVM・QBE・WAT・直接ASM・自前オブジェクトで実行します。C・LLVMは最適化なし/ありで照合し、呼び出し先の失敗が定義ファイル内の式を指すこと、配列代入の左辺が失敗すれば右辺の関数を実行しないことも検査します。ツールがなければ未実行を明示し、環境変数で指定したツールが使えなければ失敗させます。WindowsではWindowsターゲット、LinuxではLinuxターゲットをテスト側が明示し、QBEはLinuxで検証します。

## 次の設計判断

最初のモジュールでは関数・型の定義を公開対象にし、読み込んだだけで実行される初期化処理は設けない方針です。実行する処理は入口ファイルと明示的な関数呼び出しに置きます。循環importは最初は診断し、名前空間の衝突や非公開名への参照を明示的に拒否します。これらの規則と構文は次の段階で具体化します。パッケージ配布・動的ロード・共有可変なグローバル状態は、この土台の実装に含めません。
