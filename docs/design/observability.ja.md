# 可観測性の契約

[English](observability.en.md)

## 目的

Primerの観測機能が守るべき境界を定めます。

Primerは、ソースコードから生成物に至る変換過程を観測できることを重視します。観測可能であることと、外部からコンパイル処理へ干渉できることは区別します。

## 観測と制御の分離

- 観測用APIは読み取り専用とします。
- 外部からコンパイラ内部の状態を直接書き換えられるAPIを設けません。
- 書き換え、プラグイン、フックは、観測とは別の機能および権限として扱います。
- 観測データに含まれる識別子は、操作権限として扱いません。

## 内部可観測性

- トークン、AST、意味解析結果、IRの間で、各要素の由来を追跡できる状態を保ちます。
- Primer IRの文と式には、一回のコンパイル内で一意な決定的`NodeId`を付けます。`NodeId`とソース位置を表す`Span`は区別します。
- 構文要素のソース範囲を保持し、bytecode命令には元のPrimer IR `NodeId`と診断用`Span`、またはコンパイラ生成であることを示す出自を付与します。
- コンパイラが生成した要素と、追跡情報を失った要素を同じ状態で表しません。
- 観測用データは、コンパイラ内部の状態から切り離した読み取り専用の情報として提供します。
- 観測処理からコンパイル処理へ情報を戻し、変換結果を変更することを認めません。

## 公開観測面

- 現在の公開契約は、Primer IRと各出力経路が生成する成果物です。
- Primer IRのテキスト表現は、文と式の`NodeId`を`#N`として公開します。
- 内部で観測情報を保持することと、それを公開互換APIにすることは区別します。
- 新しい公開形式を追加する場合は、明示的にバージョン化したスキーマとして定義します。

## セキュリティ

- ソース本文やファイルパスは、利用者が明示的に要求した場合にのみ開示します。
- ターミナルへ出力する文字列では、制御文字やエスケープシーケンスを安全に扱います。
- トレース、診断、ソース断片には適切なサイズ上限を設けます。
- 環境変数、秘密情報、観測に不要な実行環境の情報を記録しません。

## 再現性

- 観測機能の有効または無効によって、コンパイル結果を変えません。
- 同じPrimerのバージョン、ソース、出力経路、ターゲット、ターゲット機能、明示的なオプションからは、決定的な観測結果を生成します。
- `NodeId`はこの条件の下で決定的ですが、ソース編集やPrimerのバージョン変更をまたぐ永続IDではありません。
- タイムスタンプ、ランダムな識別子など、偶発的な非決定性を観測結果へ含めません。

## LLVMの出自注釈

`emit-llvm --annotate-origins`は、既存のLLVM成果物に読み取り専用のコメントを加えます。形式は`; primer-origins v1`で識別します。

```llvm
; primer-origin: #7 bytes 208..235
  %tmp2 = call i1 @primer.string.equal(%primer.string %tmp1, %primer.string { ptr @primer.string.1, i64 10 })
```

これはLFで保存した`examples/string_origins.prim`の`echo(left) == "日本語\0"`に対応します。`emit-ir`の`#7 eq.string(...)`から同じ比較へ辿れます。範囲は元の入力のUTF-8バイト位置で、終端を含みません。CRLFの入力ではその分だけ位置が変わります。

Lowererは各命令の本体と別に`Source { NodeId, Span }`または`Synthetic`を保持します。子の式を処理した後は親の出自へ戻し、比較・出力・短絡評価の分岐の由来を取り違えないようにします。EmitterはこのバックエンドIRだけを読みます。

注釈は次の注釈までの命令群に適用します。一つのPrimer式から複数命令が生まれる場合があり、命令を生成しないリテラルなどは個別の注釈を持ちません。モジュールの定数配置、共通補助関数、スタック領域、引数の保存、起動処理は`synthetic`です。これは生成された処理だと明示するもので、ソース位置を失った状態の代用ではありません。利用箇所の命令から出自を追います。外部コンパイラによる最適化後の対応やデバッグ情報は保証しません。

注釈にはソース本文・パスを含めません。注釈の有無はloweringに入力せず、出力時のコメント追加だけを切り替えます。注釈を除いたLLVMは通常出力と一致し、実行結果も同じであることをexampleで検証します。

最初の対応経路はLLVMです。既存の公開観測面であるIRと生成物を使い、内部状態を書き換える窓口は追加しません。IRと注釈付きLLVMの対は`tests/fixtures/observation/string-origins/expected/`に固定しています。
